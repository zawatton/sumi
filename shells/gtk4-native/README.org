#+TITLE: sumi — native GTK4 shell (live)
#+STARTUP: showall

The *native* shell: a GTK4 application that runs a *live render loop* over the
sumi command vocabulary — no webview. This is Phase 4, *model A*
(command-stream / IPC): the nelisp program and the renderer are decoupled by the
stream of =(name, args, text)= commands (the live form of =frame.json=).

* The loop

Each ~16 ms tick:

1. read input — keyboard events become a =sumi_input::InputState= (logical
   buttons + HSP-style =stick= mask, the same vocabulary the web binding uses);
2. ask the [[file:src/source.rs][=CommandSource=]] for a frame, given that input — this is the
   nelisp *program's* role;
3. render the frame through the =CairoBackend= into the =DrawingArea=.

The =CommandSource= trait is the seam where a nelisp program plugs in.

* Sources

- *BoxDemo* (default) — an in-process stand-in: a box you move with the arrows /
  WASD. Proves the input → program → commands → render loop end to end.
- *StdinSource* (=SUMI_STDIN=1=) — the real IPC path: each line of stdin is
  one frame (a JSON array of ={name, nums, text?}=, the =frame.json= shape). A
  nelisp program drives the window with:

#+begin_src sh
  nelisp-program | SUMI_STDIN=1 sumi-gtk4-native
  # or replay a single captured frame:
  node -e "process.stdout.write(require('fs').readFileSync('../../frame.json','utf8').replace(/\n/g,''))" \
    | SUMI_STDIN=1 cargo run
#+end_src

* Build / run

Windows needs the GNU toolchain + MSYS2 GTK4 (the Cairo backend's requirement);
Linux uses system GTK4.

#+begin_src sh
  PKG_CONFIG_PATH=/c/msys64/mingw64/lib/pkgconfig PATH="/c/msys64/mingw64/bin:$PATH" \
    cargo +stable-x86_64-pc-windows-gnu run
  # headless smoke: scripts "hold right" for ~40 ticks, writes sumi-live.png, quits
  SUMI_AUTOQUIT=1 cargo +stable-x86_64-pc-windows-gnu run
#+end_src

Standalone crate (own =[workspace]=, parent excludes =shells/=) so the GTK4 dep
tree stays out of =cargo test --workspace= / CI.
