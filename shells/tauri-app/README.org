#+TITLE: nelisp-gui — Tauri shell
#+STARTUP: showall

A thin *Tauri* (Rust) application shell that hosts the nelisp-gui *Canvas backend*
in a WebView. It is the Tauri counterpart of the Electron shell: the Rust side
carries *no drawing logic* — it only opens the window. The same
=backends/canvas/= code renders the same vocabulary, unchanged.

* Layout

| file                | role                                                            |
|---------------------+-----------------------------------------------------------------|
| =Cargo.toml=        | standalone crate (own =[workspace]=) — kept out of the parent   |
|                     | workspace so =cargo test --workspace= / CI skip the WebView deps |
| =build.rs=          | vendors =../../backends/canvas/src/*.js= + =../../frame.json=    |
|                     | into =dist/= (single source of truth stays in the library)      |
| =tauri.conf.json=   | window + =frontendDist: dist=                                    |
| =src/main.rs=       | =tauri::Builder= → opens the WebView; =NELISP_GUI_AUTOQUIT=      |
| =dist/index.html=   | imports =./lib/index.js=, renders =./frame.json= to a canvas    |

=dist/lib/= and =dist/frame.json= are generated by =build.rs= and git-ignored.

* Build / run

Windows uses the default *MSVC* toolchain + *WebView2* (bundled with Windows 11) —
no GTK, no MSYS2. Linux uses WebKitGTK (=libwebkit2gtk-4.1-dev=).

#+begin_src sh
  cargo run                       # from shells/tauri-app/
  NELISP_GUI_AUTOQUIT=1 cargo run # open, then close after ~4s (smoke)
#+end_src

* Why standalone

The Tauri / WebView dependency tree is large and platform-specific. Keeping this
crate out of the parent cargo workspace means =scripts/check.sh= and CI stay fast
and don't need a WebView toolchain; the shell is built on demand.
